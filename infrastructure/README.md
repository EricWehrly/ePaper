# ePaper Chisel Infrastructure

This Terraform configuration sets up an AWS-based Chisel tunnel to replace ngrok for the ePaper project. It provides a self-managed, reliable tunnel solution with your own domain.

## Architecture

```
Raspberry Pi (ePaper) → Chisel Client → Internet → AWS (Chisel Server) → Your Domain
```

### Components Created

- **VPC with public subnet** - Isolated network for the inlets server
- **EC2 instance** - Runs the Chisel server with nginx reverse proxy
- **Elastic IP** - Stable public IP address
- **Route 53 DNS record** - Points your domain to the server
- **SSL Certificate** - Automatic Let's Encrypt certificate via certbot
- **Security Group** - Firewall rules for HTTP/HTTPS/Chisel access

## Prerequisites

1. **AWS Account** with appropriate permissions
2. **Domain registered** with Route 53 hosted zone
3. **AWS CLI configured** with your credentials
4. **Terraform installed** (>= 1.0)
5. **AWS Key Pair created** for EC2 SSH access

## Setup Instructions

### 1. Configure Variables

Copy the example variables file and customize it:

```bash
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars` with your values:

```hcl
domain_name = "epaper.yourdomain.com"    # Your subdomain
```

Note: Chisel authentication is automatically generated by Terraform.

### 2. Deploy Infrastructure

```bash
terraform apply
```

That's it! Terraform will initialize, plan, and deploy everything.

### 3. Client Configuration

The Chisel client is integrated into the main docker-compose.yml file. No separate configuration needed - it will automatically connect to your deployed server when you run:

```bash
docker compose up -d
```

### 4. Update ePaper Configuration

Update your ePaper project to use the new domain instead of ngrok:

1. **Update OAuth redirect URIs** in Google Cloud Console to use `https://epaper.yourdomain.com`
2. **Remove ngrok configuration** from docker-compose.yml
3. **Update any hardcoded ngrok references** to use your domain

## Verification

1. **Check server status**: Use SSM Session Manager
   ```bash
   aws ssm start-session --target $(terraform output -raw ssm_connection | cut -d' ' -f4)
   # Then: docker ps && sudo systemctl status nginx
   ```

2. **Test tunnel**: Access your domain in a browser
   ```bash
   curl https://epaper.yourdomain.com
   ```

3. **Monitor logs** on Raspberry Pi:
   ```bash
   docker logs chisel-client -f
   ```

## Cost Estimate

- **EC2 t3.micro**: ~$8.50/month (free tier eligible for 12 months)
- **Elastic IP**: $0 (while attached to running instance)
- **Route 53**: $0.50/month per hosted zone + $0.40 per million queries
- **Data transfer**: ~$0.09/GB out

**Total**: ~$9/month (much less than ngrok Pro)

## Security Notes

1. **Restrict SSH access**: Update `allowed_ssh_cidrs` in terraform.tfvars to your IP range
2. **Token security**: Chisel authentication is managed automatically by Terraform
3. **Monitor access**: Check CloudWatch logs for unusual activity
4. **Updates**: Regularly update the EC2 instance with security patches

## Maintenance

### Update Chisel
Chisel runs in Docker containers and is automatically updated when you rebuild:

```bash
docker compose pull chisel-client
docker compose up -d chisel-client
```

Server updates are handled via Terraform redeployment.

### SSL Certificate
Certificates are automatically renewed by certbot. Check renewal:
```bash
sudo certbot certificates
```

## Troubleshooting

### Common Issues

1. **DNS not resolving**: Wait 5-10 minutes for DNS propagation
2. **SSL certificate failed**: Check domain ownership and DNS settings  
3. **Tunnel not connecting**: Check client logs with `docker logs chisel-client`
4. **502 Bad Gateway**: Check if Chisel client is running on Raspberry Pi

### Logs to Check

- **Server logs**: `docker logs chisel-server -f` (via SSM)
- **Client logs**: `docker logs chisel-client -f`  
- **Nginx logs**: `sudo tail -f /var/log/nginx/error.log` (via SSM)
- **Certbot logs**: `sudo tail -f /var/log/letsencrypt/letsencrypt.log` (via SSM)

## Cleanup

To destroy all resources:
```bash
terraform destroy
```

**Warning**: This will permanently delete all AWS resources created by this configuration.
